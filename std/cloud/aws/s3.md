# Intent

이 패키지는 [`std/cloud/objectstorage.md`](../objectstorage.md) 추상 계약의 AWS 구현이다 — 같은 계약의 [GCP 구현](../gcp/storage.md)/[Azure 구현](../azure/blobstorage.md)도 참고할 수 있다.

이미지·빌드 산출물·저장 파일처럼 크기가 크거나 여러 서버·클라이언트가
공유해서 읽어야 하는 바이너리 데이터를 다룰 때 쓴다. 목적은
[`std/io/file.md`](../../io/file.md)(로컬 디스크 임의 경로)나
[`std/web/storage.md`](../../web/storage.md)(브라우저 오리진 안의 작은
값)와 비슷하게 "데이터를 남기고 다시 읽는다"는 것이지만, **모양이
다르다**: 경로 계층이 아니라 버킷 하나 안의 평평한(flat) 문자열
키(key)로 접근하고, 네트워크 너머의 공유 저장소이며, 여러 클라이언트가
동시에 같은 객체를 읽고 쓸 수 있다. 실제 존재하는 서비스(AWS S3)의
API이므로 새로 설계할 대상이 아니다(`kind: native`, SPEC.md 1.2절).

# Domain

## Class: S3.ObjectSummary

`listObjects`의 결과 한 항목이다.

멤버:
- key: string
- size: int — 바이트 단위.
- lastModified: DateTime
- eTag: string — 실제로는 보통 객체 내용의 MD5 기반 값(멀티파트
  업로드된 객체는 다른 형식이다) — 이 계약은 "내용이 바뀌면 값도
  바뀌는 불투명한 식별자"로만 다룬다.

## Class: S3.Client

생성자:
- S3.Client(bucket: string, region: string)
  설명: 이 클라이언트가 다룰 버킷과 리전을 고정한다. **접근 키(access
  key)는 생성자 인자로 받지 않는다** — 실제로는 환경 변수, IAM
  역할, 또는 자격 증명 파일에서 SDK가 알아서 읽는 것이 표준 관례다
  (아래 Constraints).

메서드:
- putObject(key: string, content: bytes, contentType: string?) -> void
  설명: 실제 `PutObject` 호출에 대응한다. key가 이미 있으면 덮어쓴다
  (버전 관리를 켜지 않았다면 이전 값은 사라진다).
- getObject(key: string) -> bytes
  설명: `GetObject`에 대응한다. key가 없으면 오류를 낸다(실제 S3의
  `NoSuchKey`).
- exists(key: string) -> boolean
  설명: `HeadObject`에 대응한다 — 본문은 내려받지 않고 존재만
  확인한다.
- deleteObject(key: string) -> void
  설명: key가 없어도 오류를 내지 않는다(실제 S3 `DeleteObject`의
  동작 — 멱등적이다).
- listObjects(prefix: string?) -> list<S3.ObjectSummary>
  설명: `ListObjectsV2`에 대응한다. prefix를 주면 그 접두어로 시작하는
  키만 반환한다. 한 번 호출에 최대 1000개까지만 반환하는 실제 API
  제약을 이 계약도 그대로 따른다(아래 Constraints).
- getPresignedUrl(key: string, expiresInSeconds: int) -> string
  설명: 자격 증명 없이도 일정 시간 동안 이 key에 접근할 수 있는
  서명된 URL을 만든다(SDK별로 실제 이름은 다르다 — 예: Python
  boto3의 `generate_presigned_url`, JS SDK의 `getSignedUrl`).

# Interface

## Library

`client = S3.Client("my-bucket", "ap-northeast-2")`로 클라이언트를 만든
뒤 `putObject`/`getObject`로 객체를 올리고 내려받습니다. 존재 여부만
필요하면 `getObject`로 통째로 받지 말고 `exists`를 씁니다.

# Constraints

- 실제 AWS SDK(Python boto3의 `boto3.client("s3")`, JavaScript AWS SDK
  v3의 `S3Client` + `PutObjectCommand`/`GetObjectCommand` 등, C++
  `aws-sdk-cpp`의 `Aws::S3::S3Client`)에 매핑한다 — 여기 메서드 이름은
  개념적인 것이고, SDK마다 실제 이름(`listObjects`가
  `ListObjectsV2Command`가 되는 식)이 조금씩 다르므로 트랜스파일 시점에
  대상 SDK의 실제 이름으로 바꾼다.
- 이름 바꾸기(rename)에 해당하는 API가 없다 — 바꾸려면
  `getObject` + `putObject`(새 key) + `deleteObject`(옛 key)로 복사 후
  지워야 한다.
- 2020년 12월부터 S3는 모든 리전에서 강한 읽기-후-쓰기 일관성(strong
  read-after-write consistency)을 보장한다 — `putObject` 직후
  `getObject`/`listObjects`가 항상 최신 값을 반영한다.
- [`std/io/file.md`](../../io/file.md)와 달리 경로 계층(디렉터리)이 실제로
  존재하지 않는다 — key에 `/`가 들어 있어도 콘솔에서 폴더처럼 보일
  뿐, 실제로는 평평한 문자열 키 하나다.
- [`std/web/storage.md`](../../web/storage.md)와 반대로 이 패키지는
  접근 키를 안전하게 보관할 수 있는 서버/백엔드 환경에서만 써야 한다 —
  브라우저(클라이언트) 코드에 접근 키를 직접 심으면 안 된다. 브라우저에서
  직접 올려야 한다면 서버가 발급한 `getPresignedUrl`을 쓴다.

# Examples

## 예제: 쓰고 다시 읽기

호출 (순서대로): `client.putObject("images/logo.png", pngBytes, "image/png")`,
`client.getObject("images/logo.png")`

기대 동작: 두 번째 호출은 `pngBytes`와 동일한 바이트를 반환한다.

## 예제: 없는 키

호출: `client.getObject("없는/키")`

기대 동작: 오류를 낸다(`NoSuchKey`).

# Open Points

- 멀티파트 업로드(큰 파일을 여러 조각으로 나눠 올리는 것), 버전 관리
  (versioning), 버킷 정책·ACL, 수명 주기(lifecycle) 규칙은 이 버전의
  범위 밖이다.
- `listObjects`의 continuation token 기반 페이지네이션(1000개 초과)은
  다루지 않는다.
- `Cache-Control` 등 CDN 캐싱과 관련된 객체 메타데이터 헤더 설정은
  `putObject`가 아직 다루지 않는다 — [`std/cloud/aws/cloudfront.md`](cloudfront.md)와
  연동할 때 필요하다(그 파일의 Open Points 참고).
