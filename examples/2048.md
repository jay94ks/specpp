# Meta

- name: 2048
- version: 0.1.0
- description: 4x4 보드에서 방향키로 타일을 밀어 합치는 숫자 퍼즐 게임.
- target: 미지정 — AI가 상황에 맞게 제안. Windows에서는 DirectX(Direct2D)
  기반 렌더링을 우선한다 (아래 Constraints 참조).

# Intent

[namu.wiki의 2048 문서](https://namu.wiki/w/2048%28%EA%B2%8C%EC%9E%84%29)에
묘사된 게임을 그대로 옮긴다: 4x4 보드, 방향키로 모든 타일을 한 방향으로
밀면 같은 숫자끼리 인접했을 때만 합쳐지고(한 번의 이동에서 3~4개가 한꺼번에
합쳐지지 않는다), 이동마다 빈 칸에 새 타일(2가 90%, 4가 10% 확률)이 생긴다.
2048 타일을 만들면 클리어, 보드가 꽉 차고 더 합칠 수 없으면 게임 오버다.

# Domain

## Class: Game2048.Game

멤버:
- grid: list<list<int>> — 4행 4열. 각 칸은 타일 값이거나, 비어있으면 0.
- score: int — 기본값 0.

생성자:
- Game()
  설명: grid를 전부 0으로 채운 뒤 `spawnRandomTile()`을 두 번 호출해 시작
  타일 두 개를 놓는다.
- Game(rng: () -> float)
  설명: 난수 소스를 직접 지정한다 (0.0 이상 1.0 미만을 반환하는 함수) — 자동
  테스트에서 타일 생성 결과를 고정하고 싶을 때 쓴다. 지정하지 않으면
  [`std/system/random.md`](../std/system/random.md)를 쓴다.

메서드:
- move(direction: enum(Up | Down | Left | Right)) -> boolean
  설명: 보드 전체를 direction 방향으로 민다. 반환값은 이 호출로 grid가 실제로
  바뀌었는지(하나라도 이동/합쳐졌는지)이다 — 바뀌지 않았으면 false.
  절차:
  1. direction과 나란한 각 줄(가로 이동이면 각 행, 세로 이동이면 각 열)마다
     따로 처리한다.
  2. 그 줄에서 0이 아닌 값들만, 원래 순서를 유지한 채 direction 쪽으로
     모은다.
  3. 모은 값들을 direction 쪽부터 순서대로 훑으면서, 바로 다음 값과 같고
     아직 이번 이동에서 합쳐진 적이 없으면 하나로 합친다(값을 2배로 하고
     score에 그 합쳐진 값을 더한다). **합쳐져서 만들어진 값은 같은 이동
     안에서 다시 합쳐지지 않는다** — 예를 들어 `[2, 2, 2, 2]`를 왼쪽으로
     밀면 `[4, 4, 0, 0]`이 되어야 하고 `[8, 0, 0, 0]`이 되면 안 된다.
  4. 합쳐진 결과를 direction 쪽부터 채우고 나머지 칸은 0으로 채워 그 줄을
     완성한다.
  5. 모든 줄을 처리한 뒤, grid가 이동 전과 하나라도 다르면 true, 완전히
     같으면 false를 반환한다.
- spawnRandomTile() -> void
  설명: grid에서 값이 0인 칸 중 하나를 무작위로 골라, 90% 확률로 2를, 10%
  확률로 4를 놓는다. 빈 칸이 없으면 아무 일도 하지 않는다.
- isGameOver() -> boolean
  설명: 빈 칸(0)이 하나도 없고, 상하좌우로 인접한 두 칸의 값이 같은 경우도
  하나도 없으면 true.
- hasWon() -> boolean
  설명: grid 안에 2048 이상인 값이 하나라도 있으면 true.

불변식:
- score는 절대 감소하지 않는다.
- grid의 모든 값은 0이거나 2의 거듭제곱이다.

test_required Game2048.Game {
  - 같은 값 두 타일이 인접하면 이동 시 하나로 합쳐지고, score가 그 합쳐진
    값만큼 증가한다.
  - `[2, 2, 2, 2]`를 한쪽으로 밀면 `[4, 4, 0, 0]`이 되어야 한다 (연쇄 합병
    금지).
  - 16칸이 모두 차 있고 상하좌우로 합칠 수 있는 칸이 없으면 `isGameOver()`는
    true다.
  - 어느 방향으로도 아무것도 움직이거나 합쳐지지 않으면 `move()`는 false를
    반환하고 grid는 그대로다.
}

# Behavior

## Feature: 방향키로 한 번 이동

설명: 사용자가 화살표 키를 누르면 그 방향으로 보드를 한 번 이동시킨다.

입력:
- direction: enum(Up | Down | Left | Right)

절차:
1. `Game2048.Game.move(direction)`을 호출한다.
2. 반환값이 true(보드가 바뀜)이면 `spawnRandomTile()`을 호출한다. false면
   아무것도 하지 않는다 (빈 이동에는 새 타일이 생기지 않는다).
3. 화면을 다시 그리도록 요청한다.
4. `hasWon()`이 true이고 이전 상태에서는 false였다면 클리어를 알린다.
5. `isGameOver()`가 true면 게임 오버를 알린다.

출력:
- 없음 (부수효과로 게임 상태와 화면이 갱신된다).

예외:
- 없음.

# Interface

## GUI

[`std/ui/canvas.md`](../std/ui/canvas.md) 기반. `CanvasWindow` 하나에 4x4
보드를 그린다.

- `onKeyDown`: 방향키(Up/Down/Left/Right)를 `Behavior.방향키로 한 번 이동`의
  `direction`에 매핑한다. 그 외 키는 무시한다.
- `onRender`: 매번 `canvas.clear(...)`한 뒤, `grid`의 16칸을 각각
  `canvas.fillRect(...)`로 채우고(값에 따라 다른 배경색 — 예: 2는 밝은
  베이지, 4는 진한 베이지, 8은 주황, ... 2048은 금색), 값이 0이 아닌 칸에는
  `canvas.drawText(...)`로 숫자를 표시한다. 상단에 `score`도 함께 표시한다.

# Constraints

- Windows에서는 [`std/windows/direct2d.md`](../std/windows/direct2d.md)의
  DirectX(Direct2D)로 렌더링하는 것을 우선한다. 다른 플랫폼/언어로
  트랜스파일할 때는 [`std/ui/canvas.md`](../std/ui/canvas.md)의 계약을
  만족하는 다른 2D 렌더러(예: Python `tkinter.Canvas`)로 대체한다 — 게임
  로직(`Game2048.Game`)은 렌더러와 무관하게 그대로 재사용한다.
- GUI가 없는 실행 환경에서는 실행할 수 없다.

# Examples

## 예제: 인접한 두 타일이 합쳐진다

전제: 한 행이 `[2, 2, 0, 0]`이다.

호출: 그 행을 왼쪽으로 미는 이동(`move(Left)`)을 한다.

기대 동작: 그 행은 `[4, 0, 0, 0]`이 되고, `score`가 4만큼 증가한다.

## 예제: 한 번의 이동에서 연쇄 합병은 없다

전제: 한 행이 `[2, 2, 2, 2]`이다.

호출: 그 행을 왼쪽으로 미는 이동을 한다.

기대 동작: 그 행은 `[4, 4, 0, 0]`이 된다 (`[8, 0, 0, 0]`이 아니다).

## 예제: 움직일 것이 없으면 아무 일도 없다

전제: 한 행이 `[4, 2, 0, 0]`이고, 그 행을 이미 왼쪽 끝까지 민 상태다.

호출: 그 행을 다시 왼쪽으로 미는 이동을 한다.

기대 동작: `move()`는 false를 반환하고, grid는 바뀌지 않으며, 새 타일도
생기지 않는다.

## 예제: 게임 오버 판정

전제: 보드가 16칸 모두 차 있고, 상하좌우로 인접한 어떤 두 칸도 값이 같지
않다.

호출: `isGameOver()`

기대 동작: `true`를 반환한다.

# Open Points

- 실행 취소(undo), 최고 점수 저장은 이 버전의 범위 밖이다.
- 3x3/5x5/6x6 같은 보드 크기 변형은 다루지 않는다 — 4x4 고정이다.
